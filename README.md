# prd

**Скилл для агента, который превращает описание инициативы в PRD, задачи и готовый код.**

Вы описываете, что нужно сделать. Дальше агент сам поднимает контекст из репозитория, git-истории, живых спек и журнала правок, задаёт вопросы только там, где в задаче действительно есть развилка, пишет PRD и спек-дельты, режет их на задачи, исполняет каждую отдельным агентом с чистой памятью — и в конце проверяет результат по вашему изначальному тексту, а не по собственному пересказу.

Документы ложатся в Obsidian-vault связным бандлом инициативы, код — в отдельную ветку с коммитом на задачу. Никаких зависимостей: скилл самодостаточен.

Работает в Claude Code, Cursor, Codex и других агентах, которые понимают формат skills.

---

## Установка

```bash
npx skills add thothlab/prd-autopilot
```

Дальше установщик спросит, что и куда ставить. Если хочется без диалога:

```bash
npx skills add thothlab/prd-autopilot --skill prd -a claude-code -g -y
```

`--skill prd` — поставить только этот скилл · `-a claude-code` — для Claude Code · `-g` — глобально, во всех проектах (без флага — только в текущей папке) · `-y` — не задавать вопросов.

Локальный путь установщик тоже принимает, репозиторий необязательно должен быть на GitHub:

```bash
npx skills add ~/Documents/Projects/prd-autopilot --skill prd -a claude-code -g -y
```

Нужен [Node.js](https://nodejs.org) — больше ничего. После установки **перезапустите сессию агента**: скиллы читаются при старте.

> **Если у вас уже был свой `/prd`** в `~/.claude/skills/prd/`, глобальная установка займёт то же место. Уберите старую копию из-под git в своём конфиг-репозитории — иначе две версии разъедутся, а `npx skills update` будет молча ничего не делать: он сверяет версию источника, а не файлы на диске.

## Как пользоваться

Откройте агента в папке проекта:

```
/prd избранное: кнопка на карточке, экран со списком, пустое состояние
```

Инициатива крупная — опишите её в файле и передайте путь; агент прочитает файл, а копию положит рядом с PRD как эталон для финальной сверки:

```
/prd deep docs/идея.md только без синхронизации между устройствами
```

```
/prd manual T-1234 — миграция каталога на новый контракт бэка
```

Первым делом агент сообщит, как он настроен и куда пишет, и откроет дашборд:

```
Полуавтомат, обычная глубина: спрошу только то, что в запросе не определено, остальное решу сам.
Документы — <vault>/Projects/example/favorites/PRD/, код — ветка codex/prd-03-favorites-list.
Дашборд открыл, он обновляется сам. Память проекта пишу в CLAUDE.md — скажи, если не туда.
```

## Настройки

Три независимые ручки, все необязательные. Слова пишутся после `/prd` в любом порядке.

**Сколько у вас спрашивают** — режим:

| | Как включить | Что происходит |
|---|---|---|
| Полный автомат | `/prd full …` | Вопросов нет вообще. Все решения, принятые за вас, перечислены в итоговом отчёте |
| Полуавтомат *(по умолчанию)* | ничего писать не нужно | Спрашивают только то, что запрос оставил открытым: обычно от двух до восьми вопросов, иногда ни одного |
| Интервью | `/prd interview …` | Спрашивают про каждую развилку, включая те, что полуавтомат закрыл бы сам |
| Ручной | `/prd manual …` | Те же вопросы плюс ваше «ок» на PRD и на список задач |

**Сколько додумывают за вас** — глубина:

| | Как включить | Что происходит |
|---|---|---|
| Строго | `/prd strict …` | Ровно то, что вы написали, и ничего сверх. Обработка ошибок и пустых состояний остаётся: требование без неё нерабочее |
| Обычная *(по умолчанию)* | ничего писать не нужно | Прорабатывается то, где пробел заметно испортит результат |
| Максимальная | `/prd deep …` | Каждое требование проходит полный список: неверный ввод, отказ бэка, обрыв на середине, пустой экран, самый первый запуск, права доступа, рост объёмов, последствия действия |

**Доводка до эталона** — `/prd polish …`. Когда работа собрана и принята, агент запускает результат, ставит рядом ваш эталон (скриншоты, образец текста, экран из прошлой версии) и ищет конкретные различия. Найденное становится обычными задачами с ревью и коммитами; кругов не больше трёх. **Без эталона доводка не запускается** — критику, которому не с чем сравнивать, приходится придумать стандарт самому, и дальше работа честно едет к стандарту, которого никто не выбирал.

Ни одна настройка не отменяет двух вещей: сверки результата с вашим изначальным текстом и вопроса перед необратимым — пушем, деплоем, удалением данных.

## Что здесь устроено иначе

### Запрос не растворяется по дороге

Первым делом текст разбирается на пронумерованные требования, записанные дословно. Дальше у каждого есть статус, а на каждом рубеже стоит проверка:

- когда написан PRD — **отдельный агент**, которому дали только ваш запрос и получившиеся документы (без манифеста), ищет, чего в них не хватает;
- когда нарезаны задачи — проверка идёт в обе стороны: у требования есть задача, у задачи есть требование. Обратное направление вылавливает работу, которую никто не заказывал;
- в самом конце — **слепая приёмка**: проверяющему выдают ваш исходный текст и готовый репозиторий, документы прячут. Он запускает результат и отвечает по каждому пункту: сделано, частично, нет.

Вычеркнуть требование может только тот, кто его поставил. Агент вправе предложить отложить — снять не вправе, и молчание отменой не считается.

### Факты ищутся, а не сочиняются

Это главное отличие от «напиши мне ТЗ». Прежде чем задать первый вопрос, агент читает живые спеки домена, журнал правок инициативы, соседний модуль, решающий похожую задачу принятым здесь способом, git-историю по теме и тикет, если его назвали. Каждая сущность, эндпоинт и риск в PRD **несут источник** — файл со строкой, хеш коммита, запись журнала. Строка без источника в документ не попадает: она становится вопросом или видимой заглушкой.

Побочный эффект приятный: вопросов меньше, и они другого сорта. Не «как у вас устроен сетевой слой», а «при отказе сети показываем текст или значок».

### PRD — дельта к согласованному, а не документ с нуля

У инициативы есть живые спеки — источник правды по каждому домену. Новый PRD пишет к ним дельту: `ADDED`, `MODIFIED`, `REMOVED`, требования в формулировках RFC 2119, сценарии `GIVEN / WHEN / THEN`. Влить дельту в живую спеку можно только командой `/prd archive NN` и только когда все задачи закрыты — так живая спека не начинает описывать то, чего в коде ещё нет.

### Задачи идут по одной на агента

Один агент — одна задача — чистая память — один коммит. Независимые задачи идут параллельно волнами; задачи, которые трогают общие файлы или один Gradle-проект, выстраиваются в очередь. После каждой задачи ревью по трём осям: доставлено ли то, что просил пользователь; сделано ли то, что решил PRD; годится ли код, чтобы строить на нём дальше.

Главный диалог кода не пишет вообще — он раздаёт работу, сверяет результат и коммитит.

## Дашборд

`run/<prd_XX>/dashboard.html` открывается сам в начале работы. Один статический файл: восемь этапов от подготовки до приёмки, живые таймеры, задачи по волнам, покрытие запроса, долг, тесты. Интернет не нужен, обновляется каждые десять секунд, тема и язык переключаются на самой странице.

| Показатель | О чём он |
|---|---|
| Прогресс | Насколько работа близка к концу — по этапам и задачам вместе |
| Покрытие запроса | Какая доля ваших требований действительно закрыта. Задачи бывают готовы на 100%, а запрос — на 70% |
| Долг | Заглушки, решения, принятые за вас, незаполненные переменные |
| Повторы и время на задачу | Где работа буксовала |

Сессия оборвалась — скажите «продолжи PRD»: состояние поднимется из файлов, переспрашивать ничего не придётся.

## Куда всё складывается

Хранилище выбирается обнаружением, а не вопросом:

| Что найдено | Куда пишутся документы |
|---|---|
| Obsidian-vault, лежащий под git | `<vault>/Projects/<проект>/<инициатива>/PRD/` — бандлом, с `index.md`, живыми спеками и журналом правок |
| vault не найден или не под git | `.prd/` в самом репозитории |

Имена файлов внутри одинаковые в обоих случаях:

```
prd_XX_brief.md          запрос слово в слово — не редактируется
prd_XX_manifest.md       требования R01…Rnn и судьба каждого
prd_XX_scratch.md        находки сбора контекста, каждая с источником
prd_XX_<slug>.md         сам PRD
specs/<domain>/spec.md   спек-дельты к живым спекам
prd_XX_task_NN_*.md      задачи
prd_XX_rep_NN_*.md       отчёты по задачам
run/prd_XX/              state.js и дашборд
```

Код при этом живёт в кодовом репозитории, в ветке `codex/prd-XX-<slug>`, по коммиту на задачу. **Пушится только vault; ветку кода вы отправляете сами.**

## Когда подходит, а когда нет

Подходит, если инициатива больше одной правки и её надо сначала описать, а потом сделать; если нужен PRD, который переживёт сессию, и живые спеки, которые переживут PRD; если хочется сказать «собери под ключ» и получить результат.

Не подходит для правки в одном файле — попросите сделать её напрямую. Не подходит, если вы хотите писать код вместе, строка за строкой. И не подходит, пока цель инициативы не определена: разбивать на задачи нечего.

## Обновление и удаление

```bash
npx skills update prd -g
```

Флаг `-g` — если ставили глобально. Чтобы агент увидел новую версию, перезапустите сессию.

Обновление ориентируется на версию в источнике и не смотрит на файлы у вас на диске. Поэтому правленую руками копию оно не тронет и сообщит, что всё актуально. Помогает переустановка:

```bash
npx skills remove prd -g -y && npx skills add thothlab/prd-autopilot --skill prd -g -y -a claude-code
```

Посмотреть установленное — `npx skills list`, удалить — `npx skills remove prd -g`.

## Что внутри

```
skills/prd/
├── SKILL.md                    оркестратор: режимы, фазы, гейты, выбор хранилища
├── phases/
│   ├── 0-modes.md              режимы, глубина, доводка
│   ├── 0-preflight.md          vault или репозиторий, номер PRD, ветка
│   ├── 0-instruments.md        поднять дашборд: шаблон, стартовое состояние, ритуал
│   ├── 0-memory.md             выбрать файл памяти проекта и написать скелет
│   ├── 1-manifest.md           запрос → требования, фильтр секретов
│   ├── 2-briefing.md           сбор контекста, вопросы, эталон
│   ├── 3-prd.md                PRD, спек-дельты, глубина, сверка покрытия
│   ├── 4-plan.md               разбивка на задачи, ярусы, волны
│   ├── 5-subagents.md          агенты-исполнители и контракты между ними
│   ├── 5-repair.md             ремонт, провал, поправки плана
│   ├── 6-review.md             ревью по трём осям
│   ├── 7-instruments.md        состояние прогона и дашборд
│   ├── 8-final.md              слепая приёмка и итоговый отчёт
│   ├── 9-memory.md             память проекта и журнал правок
│   ├── 10-archive.md           влить дельты в живые спеки, закрыть PRD
│   ├── polish.md               доводка до эталона — только если включена
│   ├── rationalizations.md     каталог отказов: оправдания и красные флаги
│   └── dashboard-template.html дашборд одним статическим файлом
├── references/
│   └── research.md             сбор контекста: источники, глубина, стоп-условие
└── prompts/
    ├── executor.md             инструкция исполнителю задачи
    └── craft-review.md         инструкция ревьюеру качества кода
```

Файлы `phases/` агент открывает по одному, в момент начала соответствующей фазы, — поэтому в памяти лежит ровно то, что нужно сейчас.
