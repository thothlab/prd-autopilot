<p align="center"><strong>Опиши инициативу словами — получи PRD, задачи и готовый код.</strong></p>

`prd` — скилл-фреймворк для Claude Code, Cursor и Codex. Он берёт описание инициативы, задаёт вопросы ровно там, где в ней есть развилки, сам собирает контекст по репозиторию, git-истории и журналу правок, пишет PRD и спек-дельты, режет их на задачи, исполняет каждую задачу отдельным агентом и в конце сверяет результат с тем, что вы написали в самом начале.

Пакет документов ложится в ваш Obsidian-vault как связный бандл инициативы, код — в отдельную ветку, по коммиту на задачу.

Работает сам по себе: ставить рядом ничего не нужно.

---

## Установка

```bash
npx skills add thothlab/prd-autopilot
```

Установщик спросит, какие навыки поставить и для каких агентов — просто подтвердите.

<details>
<summary>Установка одной командой, без вопросов</summary>

```bash
npx skills add thothlab/prd-autopilot --skill prd -a claude-code -g -y
```

| Флаг | Что делает |
|------|------------|
| `--skill prd` | Ставит только этот навык |
| `-a claude-code` | Ставит для Claude Code |
| `-g` | Глобально — навык доступен во всех проектах |
| `-y` | Не задавать вопросов |

Без `-g` навык встанет только в текущую папку проекта.

</details>

Установщик принимает и локальный путь — репозиторий не обязан быть на GitHub:

```bash
npx skills add ~/Documents/Projects/prd-autopilot --skill prd -a claude-code -g -y
```

**Требуется:** [Node.js](https://nodejs.org) (для `npx`) и любой поддерживаемый AI-агент. Больше ничего.

После установки **перезапустите сессию агента** — навыки читаются при старте.

> **Если у вас уже был свой `/prd` в `~/.claude/skills/prd/`** — глобальная установка встанет туда же. Уберите старую копию из-под git в вашем конфиг-репозитории, иначе две копии разъедутся, а `npx skills update` будет молча ничего не делать: он сверяет версию источника, а не файлы на диске.

## Как пользоваться

Откройте агента в папке проекта и напишите:

```
/prd форма перевода по номеру телефона: ввод, подтверждение, список последних получателей
```

Если инициатива большая — напишите её в файл и укажите путь:

```
/prd deep docs/идея.md только без истории переводов
```

```
/prd manual PIP-1234 — миграция каталога карт на новый контракт
```

Агент прочитает файл, возьмёт его содержимое как запрос, а копию положит рядом с PRD — именно с ней в конце сверяется результат.

В ответ он первым делом скажет, в каком режиме работает, куда кладёт документы, и **сам откроет дашборд**:

```
Режим: полуавтомат · глубина: обычная — спрошу только то, что в запросе не определено, дальше сделаю сам.
Документы: <vault>/Projects/mtsd/tbp-sdk-migration-2/PRD/ · код: ветка codex/prd-03-transfer-form.
Дашборд открыл — обновляется сам.
Память проекта — CLAUDE.md. Скажи, если нужен другой.
```

## Три режима

После `/prd` можно дописать, насколько плотно вы хотите участвовать. Ничего не написали — работает **полуавтомат**.

| Режим | Как включить | Что спрашивают у вас |
|---|---|---|
| **Полный автомат** | `/prd full …` или «полный автомат» | Ничего. В конце — список решений, принятых за вас |
| **Полуавтомат** *(по умолчанию)* | ничего дописывать не нужно | Только то, что в запросе не определено: обычно 2-8 |
| **Интервью** | `/prd interview …` или «погриль меня» | Все развилки, включая те, что полуавтомат закрыл бы сам |
| **Ручной** | `/prd manual …` или «ручной режим» | Те же вопросы, плюс ваше «ок» на PRD и на список задач |

**Что не меняется ни в одном режиме:** агент спросит перед необратимым — пушем, деплоем, удалением данных. И ни один режим не отключает сверку с вашим изначальным запросом.

## Глубина проработки

Отдельная ручка. Режим решает, **сколько у вас спросят**; глубина — **сколько додумают за вас**.

| Глубина | Как включить | Что делает агент |
|---|---|---|
| **Строго** | `/prd strict …` | Только то, что вы написали. Ошибки и пустые состояния всё равно обрабатываются |
| **Обычная** *(по умолчанию)* | ничего не нужно | Прорабатывает то, где пробел явно испортит результат |
| **Максимальная** | `/prd deep …` | Каждое требование прогоняется по полному списку: первый запуск, пусто, неверный ввод, отказ, обрыв, рост, права, последствия |

## Доводка до эталона

```
/prd polish форма перевода как в легаси-приложении
```

Когда работа собрана и принята, агент запускает результат, ставит рядом **ваш** эталон — скриншоты, экраны легаси, тон текста — и ищет конкретные различия. Найденное становится обычными задачами с ревью и коммитами. До трёх кругов. **Без эталона доводка не запускается** — критик, которому не с чем сравнивать, придумает стандарт, которого никто не выбирал.

## Что делает `prd` иначе

### Ваш запрос не теряется по дороге

Агент первым делом разбирает текст на **пронумерованные требования** и записывает их дословно. Дальше у каждого есть статус, и на каждом этапе стоит проверка:

- после PRD — ни одно требование не осталось без раздела, и это проверяет **отдельный агент**, которому дали только ваш запрос и PRD, без манифеста;
- после разбивки — у каждого требования есть задача, **и у каждой задачи есть требование**;
- в конце — **слепая приёмка**: агент получает только ваш исходный текст и готовый репозиторий, PRD ему не дают.

**Снять требование можете только вы.** Агент вправе предложить отложить — вычеркнуть не вправе.

### Факты ищутся, а не выдумываются

Это главное отличие от «сделай мне ТЗ». Прежде чем задать хоть один вопрос, агент читает живые спеки домена, журнал правок инициативы, соседний код-образец, git-историю по теме и тикет, если его назвали. Каждая сущность, эндпоинт и риск в PRD **несут источник** — файл со строкой, хеш коммита, запись журнала. Строка без источника в PRD не попадает: она становится вопросом или видимой заглушкой.

Побочный эффект — вопросов вам задают меньше, и они другого сорта: не «а как у вас устроен нетворк», а «лимит показываем суммой или общим текстом».

### PRD — дельта к согласованному, а не документ с нуля

У инициативы есть **живые спеки** — источник правды по каждому домену. Новый PRD пишет к ним дельту: `ADDED`, `MODIFIED`, `REMOVED`, требования в RFC 2119, сценарии `GIVEN / WHEN / THEN`. Влить дельту в живую спеку можно только командой `/prd archive NN`, и только когда все задачи закрыты — так живая спека не начинает врать раньше, чем код её догонит.

### Каждая задача — свой агент

Один агент на задачу, чистый контекст, один коммит. Независимые задачи идут параллельно волнами; задачи, которые трогают одни файлы или один Gradle-проект, — строго по очереди. После каждой задачи — ревью по трём осям: доставлено ли то, что просил пользователь; сделано ли то, что решил PRD; годен ли код, чтобы на нём строить дальше.

Главный диалог **не пишет код вообще** — только раздаёт, сверяет и коммитит.

## Прогресс видно всегда

`run/<prd_XX>/dashboard.html` **открывается сам** в начале работы. Восемь этапов от подготовки до приёмки, живые таймеры, покрытие запроса, задачи по волнам, долг, тесты. Работает офлайн, без сервера, обновляется сам каждые десять секунд. Тема и язык переключаются на самой странице.

| Показатель | Что означает |
|---|---|
| **Прогресс** | Одна цифра «сколько осталось до конца» — по этапам и задачам вместе |
| **Покрытие запроса** | Сколько ваших требований действительно закрыто. Задачи бывают готовы на 100%, а запрос — на 70% |
| **Долг** | Заглушки, решения, принятые за вас, незаполненные переменные |
| Повторы и время на задачу | Видно, где работа буксовала |

Сессия оборвалась — скажите «продолжи PRD», агент поднимет состояние из файлов и продолжит с того места, где остановился.

## Куда всё складывается

Хранилище выбирается **обнаружением, а не вопросом**:

| Найдено | Куда пишутся документы |
|---|---|
| клон Obsidian-vault с remote `openclaw_obsidian_vault` | `<vault>/Projects/<проект>/<инициатива>/PRD/` — как OKF-бандл, с `index.md`, живыми спеками и `Правки.md` |
| vault не найден | `.prd/` в самом репозитории |

Имена файлов внутри одинаковые в обоих случаях:

```
prd_XX_brief.md          ваш запрос, слово в слово — не редактируется
prd_XX_manifest.md       требования R01…Rnn и что с каждым стало
prd_XX_scratch.md        находки сбора контекста, каждая с источником
prd_XX_<slug>.md         сам PRD
specs/<domain>/spec.md   спек-дельты к живым спекам
prd_XX_task_NN_*.md      задачи
prd_XX_rep_NN_*.md       отчёты по задачам
run/prd_XX/              state.js и дашборд
```

Код при этом живёт в кодовом репозитории, в ветке `codex/prd-XX-<slug>`, по коммиту на задачу. **Пушится только vault; ветку кода вы пушите сами.**

## Когда использовать, а когда нет

**Подходит, если:**

- инициатива больше одной правки и её надо сначала описать, а потом сделать;
- нужен PRD, который переживёт сессию, и живые спеки, которые переживут PRD;
- «собери под ключ», «сделай ТЗ и разнеси по задачам», «не задавай лишних вопросов».

**Не подходит, если:**

| Ситуация | Что делать вместо |
|---|---|
| Правка в одном файле | Просто попросите её сделать |
| Хотите писать код вместе, строчка за строчкой | Работайте с агентом напрямую |
| Инициатива больше одного проекта, цель неясна | Сначала определитесь с целью |

## Обновление и удаление

```bash
npx skills update prd -g
```

Флаг `-g` — если навык ставился глобально. Чтобы агент увидел новую версию, **перезапустите сессию**.

`update` сверяет версию источника, а не файлы на диске: если локальную копию правили, он ответит «всё уже обновлено» и ничего не сделает. Лечится переустановкой:

```bash
npx skills remove prd -g -y && npx skills add thothlab/prd-autopilot --skill prd -g -y -a claude-code
```

Посмотреть, что установлено, и удалить:

```bash
npx skills list
npx skills remove prd -g
```

## Что внутри репозитория

```
skills/prd/
├── SKILL.md                    ← оркестратор: режимы, фазы, гейты, хранилище
├── phases/                    ← правила фаз, читаются по одной, в момент фазы
│   ├── 0-modes.md              режимы, глубина, доводка
│   ├── 0-preflight.md          vault или репозиторий, номер PRD, ветка
│   ├── 0-instruments.md        поднять дашборд: шаблон, стартовое состояние, ритуал
│   ├── 0-memory.md             выбрать файл памяти проекта и написать скелет
│   ├── 1-manifest.md           запрос → требования, фильтр секретов
│   ├── 2-briefing.md           сбор контекста, вопросы, эталон
│   ├── 3-prd.md                PRD, спек-дельты, глубина, гейт покрытия
│   ├── 4-plan.md               разбивка на задачи, ярусы, волны
│   ├── 5-subagents.md          агенты-исполнители и контракты между ними
│   ├── 5-repair.md             ремонт, провал, поправки плана
│   ├── 6-review.md             ревью по трём осям
│   ├── 7-instruments.md        состояние и дашборд — читается при нарезке задач
│   ├── 8-final.md              слепая приёмка и итоговый отчёт
│   ├── 9-memory.md             память проекта и журнал правок
│   ├── 10-archive.md           влить дельты в живые спеки, закрыть PRD
│   ├── polish.md               доводка до эталона — только если включена
│   ├── rationalizations.md     каталог оправданий и красных флагов
│   └── dashboard-template.html готовый дашборд, один статический файл
├── references/
│   └── research.md             как собирать контекст: источники, глубина, стоп-условие
└── prompts/                   ← материал для субагентов, не для оркестратора
    ├── executor.md             тесты, потолок контекста, контракт возврата
    └── craft-review.md         по чему судит ревьюер качества кода
```

Файлы `phases/` читаются агентом по одному, только когда начинается соответствующая фаза, — поэтому в памяти всегда лежит ровно то, что нужно сейчас.
