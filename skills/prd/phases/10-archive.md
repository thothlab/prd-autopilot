# Архивирование — закрыть PRD

Закрывает PRD после того, как все его задачи сделаны: спек-дельты вливаются в живые спеки, папка PRD уезжает в `Archive/`, индекс бандла обновляется.

**Триггер:** команда несёт `archive` (`/prd archive 02`), либо пользователь явно объявил PRD законченным. **Никогда не запускается в одном проходе с планированием и не запускается само** по окончании работы: PRD, чьи задачи ещё открыты, не архивируется, а PRD, чьи задачи закрыты, всё равно ждёт слова пользователя — это его решение, потому что меняются живые спеки.

Фазы 0-8 при этой команде не применяются. Читается только этот файл.

## Прежде чем что-то двигать

Три проверки, все дешёвые, и каждая ловит свой способ соврать живой спеке:

1. **Все задачи PRD закрыты.** `state.js` → ни одной `pending`, `in-progress`, `review`, `repair`; манифест → ни одной строки `in-ticket`. Есть незакрытые — не архивируй: вливание дельт, которых незаконченный код не реализовал, начинает врать в живой спеке, и врёт она потом всем.
   Задача помечена `failed`, а пользователь всё равно просит архивировать — это его решение; тогда затронутые требования уходят в `deferred` с причиной, а не притворяются сделанными.
2. **Слепая приёмка прошла.** `state.js` → `blind` не `null`. Не прогонялась — прогони её сейчас по `phases/8-final.md` §1, до вливания. Расхождение, найденное после архивирования, стоит правки уже согласованного поведения.
3. **Имена `MODIFIED`-требований совпадают** с блоками живых спек посимвольно. Это то, что чаще всего ломается на этом шаге, и ломается молча.

## Процедура

1. **Влить спек-дельты в живые спеки.** По каждому `<prdRoot>/specs/<domain>/spec.md`:
   - `ADDED Requirements` → дописываются в `<livingSpecs>/<domain>/spec.md` (файл создаётся, если его нет);
   - `MODIFIED Requirements` → **заменяют** совпадающий блок `### Requirement: <Имя>` в живой спеке;
   - `REMOVED Requirements` → совпадающий блок из живой спеки удаляется.

   Заголовки сценариев внутри блока переносятся как есть: живая спека — это то же самое наблюдаемое поведение, просто согласованное.

2. **Переместить папку PRD.** Всё, что относится к этому PRD, из `<prdRoot>` в `<prdRoot>/../Archive/YYYY-MM-DD-prd_XX_<slug>/` (дата — сегодняшняя, ISO). Вместе с ним уезжают `run/prd_XX/` с его `state.js` и дашбордом: они история этого PRD, а не общего каталога.

   В local-режиме то же самое, корень другой: `.prd/Archive/…`.

3. **Обновить `index.md`** бандла: PRD помечен закрытым с датой, ссылки ведут в `Archive/`, перечислены живые спеки, которые изменились.

4. **Дописать `Итоговый отчёт.md`** инициативы, если он есть: одна секция на закрытый PRD — что вошло в живые спеки, что осталось открытым. Это документ про инициативу целиком, и он единственный, кого читают, не открывая PRD.

5. **Закоммитить vault** — третий и последний коммит vault за жизнь PRD:

   ```bash
   git -C "$vault" add "Projects/<project>/<initiative>/"
   git -C "$vault" commit -m "prd-XX: архивирование — <slug>"
   git -C "$vault" push
   ```

6. **Сказать пользователю одну строку**: «PRD 03 закрыт: два требования влились в живую спеку `favorites`, папка уехала в Archive.» Ни таблиц, ни списков файлов.

## Когда что-то не сходится

- **`MODIFIED`-требование не находит блока** — имя должно совпадать с живой спекой посимвольно, с учётом регистра. Не совпало — дельта написана против имени, которого никогда не было. **Чинится дельта, а не живая спека**: выдуманный блок в живой спеке переживёт всех, кто помнил, откуда он взялся.
- **У домена ещё нет живой спеки** — ожидаемо для первого PRD, который его трогает: блок `ADDED` засевает файл.
- **`REMOVED`-требование всё ещё используется** другим живым требованием, которое на него ссылается, — не удаляй молча. Это `MODIFIED` у ссылающегося требования, и его надо написать; иначе живая спека остаётся с висящей ссылкой, а следующий PRD строит дельту на пустоте.
- **Два PRD архивируются подряд и трогают один домен** — вливай по одному, в порядке номеров, и перечитывай живую спеку между ними. Второй `MODIFIED` может быть написан против блока, который заменил первый.
- **Задача PRD ещё открыта** — не архивируй. Скажи, какая именно, и предложи либо закрыть её, либо перевести требование в `deferred` с причиной.
