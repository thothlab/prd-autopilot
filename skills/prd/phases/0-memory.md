# Фаза 0 — Поднять память проекта

Здесь происходят две вещи и больше ничего: **выбрать файл, записать скелет.** Что можно дописывать по ходу работы, полное описание, написанное с готового кода, и запись в журнал правок — всё это в `phases/9-memory.md` и читается, когда случается: второе внутри Фазы 5, остальное в Фазе 8. До появления кода ничего оттуда не применяется.

## Какой файл

Репозиторию нужен файл, который расскажет **следующей** сессии, что это за проект, — `CLAUDE.md` или `AGENTS.md`. Решается обнаружением, в этом порядке. Останавливайся на первом совпадении.

| Проверка | Файл |
|---|---|
| `CLAUDE.md` уже есть | `CLAUDE.md` |
| `AGENTS.md` уже есть | `AGENTS.md` |
| есть оба | тот, в котором уже лежит описание проекта; если ни в одном — `AGENTS.md`, а второй **не трогать** |
| каталог `.claude/`, или установлены `$CLAUDECODE` / `$CLAUDE_CODE_ENTRYPOINT` | `CLAUDE.md` |
| каталог `.cursor/` | `AGENTS.md` |
| каталог `.codex/`, или `.github/copilot-instructions.md` | `AGENTS.md` |
| ничего не совпало | `AGENTS.md` как настоящий файл **+ `CLAUDE.md` с одной строкой: `См. @AGENTS.md`** |

- **Существующий файл всегда бьёт обнаружение.** Репозиторий уже ответил на этот вопрос; задать его снова — так и получаются два наполовину заполненных файла памяти.
- **Файл-указатель пишется только в последнем случае.** Когда агент опознан, одного файла достаточно — второй это второе, что надо держать в синхроне, а держать его не будут.
- **Никогда не дублируй текст в оба файла.** Две копии описания проекта расходятся в пределах одного прогона.
- Запиши выбор в `state.js` как `memoryFile`, чтобы продолжение не выводило его заново.

**Это никогда не вопрос к пользователю** — ни в одном режиме, включая manual. Это решение о процессе, как и то, где лежат файлы задач, и Фаза 0 отвечает на такие сама. Но это и не *тайное* решение: одна строка во вступительном блоке, вместе с режимом.

> Память проекта — `CLAUDE.md`. Скажи, если нужен другой.

Сказал и пошёл. **Не жди ответа** — если пользователь позже назовёт другой файл, переключишься и перенесёшь блок; переименовать markdown ничего не стоит, потому это и не заслужило гейта.

## Скелет

Дёшево, пишется до того, как что-то сделано, и переживает прерванный прогон. Только то, что уже известно; всё, что пишет скилл, лежит между двумя метками — в любом случае, включая файл, который он создал сам:

```markdown
<!-- prd:start -->
# <Название проекта>

<Одна строка: что это и для кого.>

## Команды

| Команда | Что делает |
|---------|------------|
| `<установка>` | Установить зависимости |
| `<запуск>` | Запустить локально |
| `<тесты>` | Прогнать тесты |

## Как здесь работает /prd

Инициативы ведутся скиллом `/prd`. Требования, PRD, спек-дельты и задачи — в
`<prdRoot>`. Прогресс — `<prdRoot>/run/<prd_XX>/dashboard.html`.
Правило: требование из `prd_XX_manifest.md` может снять только пользователь.

Если работа продолжается — скажи «продолжи PRD»: состояние поднимется
из `run/<prd_XX>/state.js`, переспрашивать ничего не нужно.
<!-- prd:end -->
```

Команды, которые ещё не известны, просто отсутствуют. **Выдуманная команда хуже отсутствующей** — следующая сессия её запустит, она упадёт, и весь файл станет подозрительным.

**Всё, что пользователь написал вне меток, неприкосновенно.** Репозиторий, чей `CLAUDE.md` несёт выстраданные правила команды, обязан выйти из прогона с этими правилами целыми. Если на позднем прогоне меток нет, а разделы скилла узнаваемо на месте — оберни их, не дописывай вторую копию.

**В существующем проекте память не переписывается, а дополняется.** Скелет пишется один раз, в прогоне, который завёл файл. Для репозитория, у которого `CLAUDE.md` уже развёрнутый и живой, шаг сводится к одному: добавить блок «Как здесь работает /prd», если его нет, и не трогать больше ничего.

**В vault-режиме файл памяти не заменяет нарративные документы vault** и не пересказывает их. Он отвечает на «как работать в этом репозитории завтра»; «зачем всё это» и «что решили» живут в бандле инициативы и в живых спеках. Одна строка со ссылкой на бандл в нём уместна, пересказ бандла — нет.
