# Фаза 0 — Поднять приборы

Всё, что Фазе 0 нужно знать про дашборд, и ничего сверх. **Остальное — полная форма `state.js`, таблица этапов, что дашборд считает сам — лежит в `phases/7-instruments.md` и читается, когда нарезаны задачи.** Читать его сейчас нечего покупать, а стоит это единственного контекста, который никогда не обновляется.

Файла два, и разница между ними существенна:

- **`<prdRoot>/run/prd_XX/state.js`** — данные прогона и единственное место, куда ты когда-либо пишешь. Читается при продолжении; пользователь его не открывает.
- **`<prdRoot>/run/prd_XX/dashboard.html`** — то, что видит человек. Копируется из шаблона один раз и **дальше не редактируется никогда**. Ни сборки, ни зависимостей, ни генерации: в обычном браузере открывается двойным кликом, во встроенной панели — через один статический сервер (§3).

Страница сама перечитывает `state.js` из соседнего файла каждые десять секунд. Отсюда всё остальное: состояние хранится в одном месте, обновление стоит одной правки, и рассинхронизироваться нечему — второй копии просто нет.

## 1. Найти каталог скилла, скопировать шаблон

**Путь нужен не только ради копирования шаблона.** `prompts/executor.md` и `prompts/craft-review.md` уезжают субагентам **путями** (`phases/5-subagents.md`, `phases/6-review.md`), а после сжатия контекста вычислить их будет неоткуда. Поэтому найди каталог один раз, здесь, и запиши его в `state.js` как `skillDir`: на этой строке висят оба контракта — тот, по которому пишется код, и тот, по которому его судят.

```bash
RUN="$prdRoot/run/prd_XX"
TPL=$(find -L ~/.claude/skills ~/.agents/skills ~/.claude/plugins .claude/skills .agents/skills \
        -maxdepth 6 -path '*/prd/phases/dashboard-template.html' 2>/dev/null | head -1)
mkdir -p "$RUN" && cp "$TPL" "$RUN/dashboard.html" && echo "skillDir = ${TPL%/phases/*}"
```

**`-path '*/prd/phases/…'`, а не `-name`** — имя файла не уникально: соседний установленный скилл (например `autopilot`) кладёт свой шаблон под тем же именем, и `-name` с `head -1` выберет по порядку обхода каталога. Тогда `skillDir` укажет на чужой скилл, а `prompts/executor.md` и `prompts/craft-review.md`, которые уезжают субагентам как `$skillDir/prompts/*.md`, молча приедут чужие — вместе с чужим брендированием на дашборде.

**`find -L` и ни одной `*` в списке корней** — обе части несущие. Скиллы ставятся симлинками (`~/.claude/skills/prd` → `~/.agents/skills/prd`), и обычный `find` симлинк не проходит: он молчит, пока файл лежит прямо там. Глоб `plugins/*/` хуже: в zsh несовпавший глоб рушит команду до запуска, поиск не происходит вовсе, и `skillDir` выходит пустым — а в bash та же строка работает, из-за чего это трудно заметить.

Пустой вывод значит, что скилл лежит вне этих пяти корней: расширь поиск один раз руками и иди дальше. Никогда не генерируй шаблон заново, не читай его в контекст и не правь после копирования.

## 2. Записать `state.js`

Первая строка ровно `window.STATE =`, дальше состояние обычным JSON с отступами. Присваивание на отдельной строке — это то, что позволяет `tail -n +2 state.js | jq .` работать, и то, что делает правку ниже маленькой правкой.

Вот весь файл в момент создания — скопируй и заполни, что знаешь:

```js
window.STATE =
{
  "slug": "phone-transfer-form",
  "title": "Перевод по номеру телефона в SDK",
  "prd": "prd_03",
  "mode": "semi",
  "depth": "normal",
  "polish": null,
  "tier": null,
  "storage": "vault",
  "prdRoot": "/Users/x/Documents/vault/Projects/mtsd/tbp-sdk-migration-2/PRD",
  "livingSpecs": "/Users/x/Documents/vault/Projects/mtsd/tbp-sdk-migration-2/specs",
  "docsPath": "Projects/mtsd/tbp-sdk-migration-2/PRD/",
  "briefFile": "prd_03_brief.md",
  "memoryFile": "CLAUDE.md",
  "codeBranch": "codex/prd-03-phone-transfer-form",
  "skillDir": "/Users/x/.claude/skills/prd",
  "startedAt": "2026-08-17T14:02:06+03:00",
  "updatedAt": "2026-08-17T14:02:06+03:00",
  "finishedAt": null,
  "stages": [
    { "id": "preflight", "status": "active", "startedAt": "2026-08-17T14:02:06+03:00" },
    { "id": "manifest",  "status": "pending" },
    { "id": "briefing",  "status": "pending" },
    { "id": "spec",      "status": "pending" },
    { "id": "plan",      "status": "pending" },
    { "id": "build",     "status": "pending" },
    { "id": "review",    "status": "pending" },
    { "id": "final",     "status": "pending" }
  ],
  "requirements": {
    "total": 0, "done": 0, "inTicket": 0, "inSpec": 0,
    "placeholder": 0, "deferred": 0, "dropped": 0
  },
  "tickets": [],
  "singlePass": null,
  "tests": null,
  "debt": { "placeholders": [], "assumptions": [], "emptyEnv": [] },
  "additions": [],
  "coverage": null,
  "concerns": [],
  "reviewers": { "manifestSpec": null, "craft": null },
  "blind": null
}
```

**Поле называется `tickets`, а не `tasks`** — так его читает шаблон дашборда, и переименование сломало бы страницу. Наружу — в чате, в отчёте, на экране — это всегда «задачи».

Шесть полей существуют потому, что контекст оркестратора не переживает сжатие, а восстановить их из репозитория нельзя:

- **`skillDir`** — вычислен в §1. Без него два контракта субагентов перестают уезжать вниз, и прогон тихо вырождается в обычный вайбкодинг.
- **`prdRoot`, `livingSpecs`, `storage`** — результат поиска vault из `phases/0-preflight.md`. Искать заново после сжатия — это минуты и шанс завести второй бандл.
- **`concerns`** — отложенные находки Craft, на верхнем уровне, а не только внутри задачи: на ярусе T0 задач нет, а разбор в `phases/8-final.md` был единственным оправданием откладывания.
- **`reviewers`** — ручки двух долгоживущих ревьюеров (`phases/6-review.md`). Потерять их не смертельно; смертельно то, что кросс-задачные находки тогда не происходят вовсе.

**Все восемь этапов перечислены с первой минуты**, семь недостигнутых как `pending`. Именно это показывает пользователю весь маршрут вместо пустой страницы — шаблон рисует каждый этап, который ему дали, и ни одного, которого не дали.

`tier` остаётся `null` до Фазы 4. `polish` остаётся `null`, если параметр доводки не запрошен, — не добавляй блок на всякий случай.

**Никогда не клади сюда значение секрета.** `emptyEnv` держит только имена — в этом весь смысл списка.

**ISO 8601 со смещением**, всегда: `2026-08-17T14:02:06+03:00`. Голое `14:50` даёт невалидную дату и мёртвый прочерк на дашборде. Смотри часы командой `date -Iseconds` в момент события — **секунды часть ответа**, и колонка времён, оканчивающихся на `:00`, — видимый признак, что их писали по памяти.

## 3. Открыть один раз, самому

Объяснить, где лежит файл, и предложить сходить туда самому — плохой вариант. **Открой дашборд сразу после первой записи**, до того как Фаза 1 что-то спросит.

**Открытая страница обновляется без твоего участия**, где бы она ни открылась: ни обновлять, ни переоткрывать её не нужно. Механизм при этом не тот, который напрашивается. Встроенные панели (Claude Desktop, просмотрщики IDE) **не дают странице себя перезагрузить**: `location.reload()` не срабатывает, `<meta http-equiv="refresh">` тоже. Зато подгрузку под-ресурсов они не трогают — поэтому страница дописывает свежий `<script src="state.js?t=…">` вместо перезагрузки. Это дёшево, сохраняет позицию прокрутки и одинаково работает в обычном браузере.

**Путь A — окно, в которое пользователь и так смотрит**, и туда страница отдаётся по http, а не по `file://`. Есть у харнесса панель предпросмотра, встроенный браузер, webview — **пользуйся ими**: дашборд затем и нужен, чтобы бросить на него взгляд не переключая окон.

**`file://` в панель отдавать нельзя.** Панель встраивает HTML в `data:`-URL, а из него до `state.js` не дотянуться ничем: относительный путь никуда не ведёт, абсолютный `file://` запрещён для источника `null`, `fetch` режет CORS. Пользователь весь прогон смотрит на надпись «состояние ещё не прочитано» при совершенно исправном файле рядом.

Поэтому раздай каталог прогона по http и укажи панель на него:

```bash
RUN="$prdRoot/run/prd_XX"
PORT=$(python3 -c 'import socket; s=socket.socket(); s.bind(("127.0.0.1", 0)); print(s.getsockname()[1]); s.close()')
python3 -m http.server "$PORT" --bind 127.0.0.1 --directory "$RUN" >/dev/null 2>/tmp/prd-serve.log &
SRV=$!
curl -sf --retry 5 --retry-delay 1 --retry-connrefused "http://localhost:$PORT/dashboard.html" >/dev/null \
  && printf '%s %s\n' "$PORT" "$SRV" > /tmp/prd-serve.pid \
  || echo "сервер не поднялся — иду по пути B"
```

**Строка с `curl` и есть причина, по которой блок из трёх команд, а не из двух.** Порт был свободен в момент выбора и мог оказаться занят к моменту привязки; песочница может не дать сокет; `python3` может не понимать `--directory`. Все три случая выглядят одинаково — мгновенное падение в `/dev/null`, — и без проверки прогон запишет pid уже мёртвого процесса и отправит панель в пустоту. **Проверка — не вторая попытка**: правило ниже запрещает пробовать другой запускатель, и это не он, это выяснение, по какому из двух путей ты идёшь. Pid-файл кладётся в `/tmp`, потому что каталог прогона коммитится, а мёртвый pid с правдоподобным именем в репозитории — мусор надолго.

Запускать сервер **фоном**: на переднем плане он заблокирует всю работу. Дальше открой панель на `http://localhost:$PORT` и перейди на `/dashboard.html`. В Claude Code это `preview_start({url: "http://localhost:PORT"})` и затем `navigate` на `/dashboard.html`: голый `navigate` на localhost-порт **без** `preview_start` политика панели отклоняет, а `127.0.0.1` в URL отклоняется там, где `localhost` принимается.

**Путь B — системный браузер.** Нет встроенного просмотрщика или нет `python3` → отдай файл ОС, без сервера:

```bash
open "$RUN/dashboard.html" 2>/dev/null \
  || xdg-open "$RUN/dashboard.html" 2>/dev/null \
  || echo "открой вручную: $RUN/dashboard.html"
```

Настоящий браузер открывает `file://` как страницу и даёт ей подгрузить `state.js` из того же каталога, так что опрос работает и без сервера. Фоновая вкладка может быть придушена до одного опроса в минуту — данные отстают на минуту, но не замерзают. IDE — это путь B, а не A: `code file.html` открывает *исходник* в редакторе.

**Правила для обоих путей:**

- **Открывается ровно один раз.** Оба пути держат себя свежими. Ни один не открывает второе окно и не переоткрывает первое.
- **Никогда при продолжении в уже открытое окно.** При продолжении открывай заново, только если прошлая сессия закончилась (`finishedAt` заполнен). Живой процесс в `/tmp/prd-serve.pid` → переиспользуй его порт.
- **Неудача — не ошибка.** Безголовая машина, нет браузера, нет панели — напиши путь одной строкой и работай дальше. Не повторяй, ничего не устанавливай, не пробуй второй запускатель.
- **Не открывай в удалённой сессии.** Установлены `$SSH_CONNECTION` или `$CI` — пропусти открытие и напиши путь.
- **Один статический сервер, и только ради панели**, привязанный к `127.0.0.1` и никуда шире, поднятый один раз и убитый в Фазе 8. Он раздаёт каталог прогона; `0.0.0.0` опубликовал бы его в сеть.

Об этом говорится один раз, одной строкой, внутри вступительного блока:

> Открыл дашборд, дальше он живёт сам: http://localhost:PORT/dashboard.html

> Открыл дашборд — `run/prd_03/dashboard.html`, обновляется без меня.

## 4. Ритуал обновления — те же три движения до конца прогона

Это здесь, а не в `phases/7-instruments.md`, потому что **понадобится задолго после того, как тот файл покинул бы контекст**, и потому что это вся суть большинства обновлений:

| Когда | Что |
|---|---|
| вход в фазу | этот этап → `active` + `startedAt`; покинутый → `done` + `finishedAt` |
| запуск задачи (или целой волны) | эти задачи → `in-progress` + `startedAt` **до** ухода субагента |
| задача вернулась, начинается ревью | эта задача → `review` |
| находка ушла в ремонт | → `repair`, и `repairs` + 1 |
| задача передана свежему контексту | остаётся `in-progress`, и `handoffs` + 1 |
| закоммичено | → `done` + `finishedAt` + тесты + коммит |

Каждое из них: **правишь затронутые строки** `state.js` и двигаешь `updatedAt`. Не переписываешь файл — примерно тридцать токенов, один вызов инструмента, и экран догоняет за десять секунд, где бы он ни был открыт.

- **Привязывай правку к строке `"id"`, стоящей над изменяемым полем.** `"status": "pending"` встречается по разу на каждый этап и каждую задачу, а сразу после создания файла `updatedAt`, `startedAt` прогона и `stages[0].startedAt` — это три одинаковых строки. Правка по одному только полю попадёт не туда или не совпадёт вовсе; замена всех вхождений разом переписывает все задачи и потому ответом не бывает никогда. Не совпало — значит, файл изменился с момента последнего чтения: перечитай и переделай правку по тому, что там сейчас.
- **У задачи своё время старта.** Не время прогона и не время этапа разработки. Подставленный сюда `startedAt` прогона выглядит безобидно и делает неверными все длительности, начиная с первой строки.
- **Время старта ставится в момент старта.** Именно интервал с началом и без конца заставляет таймер идти; заполнить оба конца в самом конце — значит показать пользователю неподвижные часы ровно тогда, когда работа шла.
- **`updatedAt` двигается при каждой записи.** По нему дашборд считает «обновлено N назад» и подкрашивает строку, когда молчание затягивается: это единственный способ отличить идущую работу от умершего агента. Шаблон знает, что пишущаяся задача молчит десятками минут, и держит предупреждение до трёх четвертей часа, а между задачами — пять минут. Поэтому предупреждение означает ровно то, что написано, и выдумывать записи ради поддержания пульса не нужно.
- **`dashboard.html` после копирования не трогается**, а таблица прогресса прозой в чате не ведётся никогда.

На этом дело Фазы 0 с приборами закончено. Когда задачи нарезаны, читай `phases/7-instruments.md` — форму задачи и остальные рассуждения.
